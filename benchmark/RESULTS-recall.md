# Recall on real code: first sample (seed 2026)

**Read this first.** Scored blind with scanner 0.3.1, before any change, this sample gave **19 / 28 = 68% recall (95% CI 49% to 82%)**. Its nine misses drove the recall fixes listed in the CHANGELOG, so the table below re-scores the same files with the fixed scanner and is optimistic by construction. The number for the current scanner is the [held-out sample](RESULTS-recall-holdout.md).

Generated by `python benchmark/recall_sample.py --score`. Method and labeling rules:
the module docstring of [`recall_sample.py`](recall_sample.py); every label, with its
reason, is in [`recall_labels.json`](recall_labels.json).

Population: 833 Python files that import a crypto-capable module, in 37 pinned PyPI packages. Sample: 40 files (seed 2026), 21 of which contain at least one quantum-vulnerable usage.

## Every miss

- `pycryptodome/pycryptodome-4.2.0/lib/Crypto/SelfTest/Cipher/test_DES.py` lines 28, 195, 208, 241 (des): Single DES self-test: imports Crypto.Cipher.DES and encrypts with DES.new (56-bit DES; no family for it in the scanner)
- `pycryptodome/pycryptodome-4.2.0/src/test/make_tests_ladder_step.py` lines 7, 8, 9, 10, 11, 60, 137, 169 (ecc): Generates C tests for the Curve25519 Montgomery ladder: ref() implements the ladder step mod 2^255-19; the name appears only in the emitted C

Labels were written by reading each sampled file in full, or for long files every line a broad search for algorithm names surfaced plus its surrounding code, before the scanner was run on the sample. A usage counts when executable code uses, configures, selects, imports or implements the algorithm; names in comments, docstrings and messages, and flags that turn an algorithm off, do not.
